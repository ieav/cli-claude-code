# 长链路阅读方案(2026-11-15,源于阅读理解 RCA)

> 源起:用户问"ziv 的阅读理解能力怎么样"。RCA 结论:单次读取管道健
> 康,残余瓶颈是**看不到**(二进制盲区)与**记不住**(读入随压缩衰减)。
> 本文是"用部分内容+截断标记+文案引导读长链路逻辑"的完整方案——已
> 实施项标注 ✅,待办标注 ⬜。

## 总原则

**永不让模型处于"不知道还有没有下文"的状态。** 每一个有界读面都必
须同时给:已读内容 + 明确的截断/折叠标记 + 可执行的续读指令。信息丢
失不可完全避免(预算约束),但丢失必须**可见、可量化、可恢复**。

## 六个抓手

### ① 统一分页协议(所有有界读面)✅

| 读面 | 帽 | 标记内容 | 续读指令 |
|---|---|---|---|
| FileRead 全量 | 400 行 / 15 KiB | 真实总行数 + 已读区间 | `offset=下一行` |
| FileRead 切片 | 15 KiB 字节帽 | 同上 | 同上 |
| 工具输出进历史 | 16 KiB | 已读/总字节数 | FileRead 分页 / 收窄 Bash、Grep |
| Bash 输出 | 256 KiB 捕获 | ✅(本次)保留部分 + 帽值 | `\| head -c` / 落盘 `/tmp/x.log` + FileRead |
| Grep | 500 条 | 截断行 | 收窄 pattern/path |
| Glob | 2000 条 | 截断行 | 收窄模式/分目录 |
| WebFetch | 512 KiB 下载 / 30K 字符 | 未读字符数 | (页面级,一般够用)⬜ 大页分页待需求 |
| 折叠(压缩时) | 每回合留 8 条;≤512B 不折 | ✅(本次)256B 头 + 原始体量 | "重新调用相应工具" |

### ② 定位优先于通读 ✅

>2000 行的目标,通读 = 5+ 次迭代,不是阅读是浪费。标准姿势:
`DirTree/Glob(结构) → Grep(索引优先,字面量零进程) → FileRead offset/limit(局部窗)`。
支撑已齐:Grep 双路径(索引/真扫)、代码索引 FTS5、DirTree 剪枝表。
工具描述与错误文案均按此教学。

### ③ 会话读迹注册表(B5)✅

FileRead 成功即登记 `path + 真实总行数`(32 条环形,按 path 去重,并
行安全)。每个提示符快照冻结,随请求尾注入(F1 机制,不占历史预算)。
模型全程知道**本会话读过哪些文件、各多少行**——折叠/瘦身后重读是一次
零 IO 调用(FileStateCache)。衰减从"记不住读过什么"降为"内容可一键
取回"。

### ④ 大输出落盘缓冲 ✅(本次补齐文案)

Bash 超帽标记现含两条出路:管道收窄(`| head -c 20000` / `| tail` /
`| grep`),或**落盘分页**:`重定向 /tmp/out.log` → FileRead offset/limit。
配合 run_in_background + `.ziv/tasks/<id>.log`,长构建输出有三条消费
路径,全是"部分内容+标记"形态。

### ⑤ 摘要承载结构(压缩后的理解存续)✅(hybrid 路径)

hybrid 摘要指令含 "Files and Code Sections" 段——文件路径、接口、决
策进摘要。已知边界:flash/本地档模型与预算耗尽时落 phi 兜底,无 LLM
摘要(分级差异,产品决策,暂不改)。

### ⑥ 符号级跳读 ⬜(已规划未实施)

tree-sitter 里程碑 2(DESIGN 规划中的 FTS5 符号旁路):`grep 符号名 →
FileRead 函数窗口`,把"定位→读"再提一级精度。触发条件不变:真实用
例喂参数再动工。

## 衰减减缓(B 链)的量价关系

- B1 折叠降级:≤512B 结果永存(状态类输出零损失);>512B 折成 256B
  头+体量标记。最坏 +11 KiB/回合,换"读过什么"的永久锚点。
- B5 读迹:~32 行常驻尾注(约 300-500 token),换全会话的读迹记忆。
- 未做(记录):FileRead 结果整体豁免折叠——预算爆炸风险(15 KiB × N
  条),与 B5 的"清单+廉价重读"相比性价比差,不做。
