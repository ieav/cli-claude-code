# ziv 配置操作规程（spec v2.1，2026-11-07）

> 本文档是配置交互的**唯一事实源**。改动任何配置相关交互前先读本文件；
> 改动后必须保持 §6 不变量成立并跑 §7 断言。历史：v2.0 修复四个取证缺陷
> （D1 回车假死 / D2 提示撒谎 / D3 保存后乱跳 / D4 盲配置），v2.1 补
> 「打开查看即退出」场景与 Esc 语义的层间统一（E1）。

## 1. 两类输入提示（顶层分类，全部提示必须归入其一）

| 类 | 判别 | 规则 |
|---|---|---|
| **编辑类**（有当前值） | 提示里写「当前 X」 | **回车=保留当前 · `-`=清除 · 输入新值=修改 · Esc/Ctrl-C=取消** |
| **新值类**（无当前值） | 要求输入一个本来不存在的东西 | **输入=确定 · 空回车或 Esc=取消** |

两类互斥：一个提示要么显示当前值（编辑类），要么不显示（新值类）。
不存在第三类。归错类 = 规则错乱，审查时按此判定。

- 编辑类：API Key、Base URL、Brave Key、Ollama Host（单/双字段编辑会话）
- 新值类：自定义模型名（`promptCustomModel`）、系统提示词正文

## 2. 交互层与进出规则（状态图）

```
ziv 提示符
  ↕  /config 进入 · Esc/q 从主菜单退出
/config 主菜单（每项右侧显示当前值）
  ↕  Enter 进入子项 · Esc/q 返回上一层
API Keys 子菜单（Key 掩码、Host 明文显示）
  ↕  Enter 进入接入编辑 · Esc/q 返回主菜单
接入编辑会话（两字段顺序问，一次保存）
  ↕  两字段都提交→保存 · 任一字段 Esc→整会话中止
```

**查看即合法**：打开任何一层只为看看、不打算改，是完全正常的使用方式——
每一层都显示当前值（主菜单行、子菜单行、编辑提示的「当前 X」），看任何
一层的数据都**不需要输入任何东西**；Esc/q 逐层退出，全程零写入。

## 3. 按键语义总表（唯一对照，层×键）

| 键 | 菜单层（select） | 编辑类提示（readLine） | 新值类提示（readLine） |
|---|---|---|---|
| Enter | 确认选中项，进入 | 提交本字段（空=保留）→ 下一字段；末字段提交后保存 | 提交；空=取消 |
| Esc | 返回上一层，不选中 | **取消整个编辑会话**，返回子菜单 | 取消，返回 |
| q | 同 Esc（菜单层专属） | 仅 Key 字段有误输守卫（见 §5） | — |
| 1-9 | 直达第 N 项（**1 基**） | 无效（被丢弃） | 无效 |
| ↑↓/jk | 移动光标 | 无效（箭头序列整条吞除） | 同左 |
| Ctrl-C | SIGINT→信号恢复终端后退出进程 | 取消（等同 Esc） | 取消 |
| 退格 | 无效 | 编辑：删一个字符 | 同左 |
| 其他控制字节 | — | 丢弃，永不入值 | 同左 |

层间一致性铁律：**Esc 在任何层的含义都是「退出当前层、零写入」**——
菜单层退出菜单、编辑层退出编辑会话。Ctrl-C 在值提示处等同 Esc，
在菜单层等同进程退出（ISIG 开），在 ziv 主提示符是双击退出协议——
三处语义不同由所在层的 guard 决定，不由 readLine 决定。

## 4. 各配置项字段表

| 菜单项 | 类别 | 字段 | `-` 语义 | 空回车（全部字段） |
|---|---|---|---|---|
| API Keys → OpenAI/Anthropic 接入 | 编辑类 | Key、Base URL 两字段 | Key→未配置；URL→恢复官方 | 未更改，不落盘 |
| API Keys → Brave Key | 编辑类 | 单字段 | 未配置 | 未更改 |
| API Keys → Ollama Host | 编辑类 | 单字段 | （无——host 恒有值） | 未更改 |
| 默认模型 | 菜单选择 | 自定义走新值类提示 | — | 取消 |
| 最大 tokens / 记忆预算 / 并发 / 回合上限 | 编辑类（数值校验） | 单字段 | — | 未更改（菜单显示当前值） |
| 权限/检查点/自动修复/提炼压缩 | 开关 | 无输入 | — | — |
| 系统提示词 | 新值类 | 单字段 | — | 取消 |
| 输出风格 | 菜单选择（default/concise 两项） | output_style | — | 取消；/style 命令直达（2026-11-09） |

两字段会话的**写入时点唯一**：Key 与 Base URL 都读完后才写 settings、
才重建 provider 缓存、才落盘。任一字段取消 = 两个字段都没发生过。

## 5. 守卫与边界

- **Base URL 拼接规则**（防「配好了却一直失败」）：ziv 直接在 Base URL 后
  拼路径——OpenAI 兼容 `{base}/chat/completions`、Anthropic 兼容
  `{base}/v1/messages`。填的 base 必须是**有权限访问目标模型**的那一级
  （同一网关不同路径权限可以不同：实测 bigmodel `/api/v1` 对 glm-5.3
  403、`/api/paas/v4` 正常，2026-11-07）。失败时 TUI 的
  `[网关返回: status=… 网关原文]` 行就是排查起点。
- **误输守卫**（仅 Key 字段）：输入 `q` / `/quit` / 含空格 → 忽略并提示，
  不写入——防「想退菜单时的手势被存成 Key 导致后续 401」。
- `-` 只在编辑类有效；输入恰好就是一个 `-` 的值不可能合法（URL/Key/
  Host 都不会是单个连字符），无歧义。
- 数值项提交后经范围校验（如 tokens 1-128000），出界只提示不落盘。
- 保存动作本身无网络往返、无自动弹菜单（D3 铁律）；网关模型发现只在
  `/model` picker 的「从网关列出模型」项，由用户主动触发，失败打报错行。

## 6. 不变量（改动者必须保持，违反即回退）

- **INV1** 值缓冲只接受可打印字节；控制字节要么编辑（退格）要么终止/
  取消（CR/LF、Esc、Ctrl-C），其余丢弃。
- **INV2** Esc 在任何层、任何字段都绝不触发写入；两字段会话写入只发生
  在两字段都提交之后。
- **INV3** 配置动作的终点是「✓ 已保存」汇总行——无网络、无连环菜单。
- **INV4** 提示显示的当前值 = settings.json 实际值（Key 掩码显示除外）。
  文案与行为不一致 = 缺陷（D2 教训）。
- **INV5** Enter 立即生效：readLine 收到孤 CR 立即结束行，只有字节已在
  缓冲时才窥望配对 LF（D1 教训——阻塞窥望让回车假死）。
- **INV6** readLine 取消返回 `null`，与「空回车提交」（返回空串）类型可
  分——多字段会话据此整会话中止（E1 教训——空串承担双义导致 Esc 蹦出
  下一字段）。

## 7. 行为断言清单（已实现，防回退）

单测（`util/menu.zig`）：Esc/Ctrl-C→null；部分输入+Esc→null；箭头/SGR
鼠标序列吞除；退格编辑；控制字节丢弃；回显；孤 CR 立即返回；CRLF 单终止；
CR 后字节留给下一读。

pty（`scripts/pty_suite.py` S6）：
1. 值提示 Esc → `[已取消]` + 菜单重绘
2. **打开 API Keys → 进 OpenAI 接入 → 第一字段 Esc → 整会话中止，
   Base URL 提示不出现，零写入**（查看场景）
3. 子菜单 Esc → 返回主菜单
4. （验收脚本内联）key 回车 0 延迟出 URL 提示；空回车→未更改不落盘；
   `-`→settings.json 字段清除；保存后无弹菜单；`/model` 含网关入口

## 8. 历史缺陷登记（为什么有这些规则）

| 代号 | 现象 | 根因 | 封口 |
|---|---|---|---|
| D1 | 回车假死，再敲一键才推进 | CR 后 peekGreedy 阻塞窥 LF | INV5 |
| D2 | 提示「回车=官方」实际不改 | 文案与行为脱节 | INV4 |
| D3 | 保存后弹模型/路由连环菜单 | 配置混入发现动作 | INV3 |
| D4 | 提示不带当前值、无保留语义 | 未设计 | §1 编辑类规则 |
| E1 | 第一字段 Esc 蹦出第二字段提示 | 取消与空提交同型（都返回空串） | INV6 |
